# Роботы TraderPro в Яндекс Облаке

Одна функция, которую по таймеру будит Яндекс. Делает ровно то же, что сейчас делает GitHub Actions
(`.github/workflows/traderpro-alerts.yml`): утренняя сводка, уведомления по позициям, бумажные сделки,
ведение, снимок для меню Telegram, автоочистка радара, перенос сделок из Telegram, отметки по позициям
Т-Банка. Скрипты те же самые — в архив кладутся файлы из `scripts/`, ничего не переписано.

**Зачем.** Расписание GitHub «best-effort»: запуски приходят с опозданием и пропусками (поэтому утренняя
сводка пришла в обед). Таймер Яндекса срабатывает по часам.

**Ничего не удаляется.** GitHub-робот, будильники Cloudflare и cron-job.org остаются как запасной
вариант. Переключение — отдельный шаг в самом конце (шаг 9), и его можно откатить обратно.

## Шаг 1. Собрать архив

В папке проекта:

```
powershell -ExecutionPolicy Bypass -File yandex\robots\build.ps1
```

Получится `yandex\robots\dist\traderpro-robots.zip` (около 12 МБ). Ключей в нём нет.

## Шаг 2. Загрузить архив в Object Storage

Архив больше 3,5 МБ, напрямую функция его не принимает. В консоли Яндекс Облака: **Object Storage** →
создать бакет (имя любое, например `traderpro-code`, доступ — «ограниченный») → загрузить
`traderpro-robots.zip`.

## Шаг 3. Создать функцию

Cloud Functions → «Создать функцию» → имя `traderpro-robots`. В редакторе:
- среда выполнения `nodejs22` (подойдёт `nodejs18`);
- способ: **«Объектное хранилище»**, выбрать бакет и файл из шага 2;
- **точка входа: `robots/index.handler`**;
- таймаут **600 секунд**, память **512 МБ**.

Функцию делать публичной **не нужно** — её будет будить только таймер.

## Шаг 4. Переменные окружения функции

Значения GitHub после сохранения не показывает, поэтому берём из первоисточников:

| Переменная | Откуда взять |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT` | Firebase → Настройки проекта → Сервисные аккаунты → «Создать новый закрытый ключ»; содержимое файла JSON целиком, одной строкой |
| `ALERT_UIDS` | ваш uid: `1stzQToO77e61ubwLuo3g5KK1DI3` (он же `OWNER_UID` в `workers/telegram-webhook/wrangler.toml`) |
| `TELEGRAM_BOT_TOKEN` | @BotFather → ваш бот → API Token |
| `TELEGRAM_CHAT_ID` | тот же, что в GitHub (число; если забыт — напишите боту и откройте `https://api.telegram.org/bot<токен>/getUpdates`) |
| `RELAY_URL`, `RELAY_KEY` | те же, что вставляли в GitHub и Cloudflare |
| `CF_API_TOKEN`, `CF_ACCOUNT_ID`, `CF_KV_NAMESPACE_ID` | Cloudflare: токен — My Profile → API Tokens (право Workers KV Storage: Edit); `account_id` и `namespace id` есть в `wrangler.toml` |
| `ROBOTS_MODE` | на первых запусках: `diag`, затем `dry` |

Ограничение Яндекса: все переменные вместе — не больше 4 КБ. Обычно хватает; если нет, секреты кладут в
Lockbox и подключают к функции.

## Шаг 5. Диагностика (`ROBOTS_MODE=diag`)

Вкладка «Тестирование» → «Запустить функцию». В ответе — что видно из Яндекса: Firestore, Telegram,
Cloudflare, посредник к Т-Банку, MOEX. Секреты не печатаются.

- Всё `ok: true`, а «Telegram напрямую» с кодом 200 — идём дальше.
- «Telegram напрямую» не открывается (`ok: false`) — в России он сейчас ограничен. Нужен посредник за границей,
  у вас два готовых варианта (выбирайте один, оба проверены тестами):
  - **Vercel (рекомендую, уже есть):** в Vercel → проект → Settings → Environment Variables добавьте
    `TELEGRAM_BOT_TOKEN` (токен бота), сделайте Redeploy. В функции Яндекса задайте
    `TELEGRAM_API_BASE` = `https://<адрес вашего сайта на Vercel>/tg`. Код: `api/tg.js` + правило в `vercel.json`.
  - **Cloudflare:** то же самое делает воркер (`/tg/…`), но его нужно передеплоить; задайте
    `TELEGRAM_API_BASE` = `https://traderpro-telegram-webhook.glebmaksimov05978.workers.dev/tg`.
  Повторите диагностику: строка «Telegram через прокси» должна дать код 200. Если Яндекс не открывает и сам
  Vercel/Cloudflare, это тоже видно в диагностике, тогда нужен третий вариант (прокси на зарубежном VPS).

## Шаг 6. Сухой прогон (`ROBOTS_MODE=dry`)

Смените переменную на `dry` и запустите. Все шаги считают и показывают в логах («ОТКРЫЛ БЫ…», «сводка (сухо)»),
но ничего не пишут и не отправляют. Логи — вкладка «Логи». Ищите ошибки вида «Нет …» или «Cannot find».

## Шаг 7. Таймер

Cloud Functions → «Триггеры» → создать → тип **«Таймер»** → функция `traderpro-robots`. Расписание
(UTC): `0/15 4-20 ? * * *` — каждые 15 минут с 7:00 до 23:45 по Москве. (Если консоль не принимает запись,
в подсказке под полем есть примеры формата; смысл — «каждые 15 минут, часы 4–20».) Нужен сервисный аккаунт с ролью
`functions.functionInvoker`.

## Шаг 8. Параллельная работа (1–2 дня)

Пока оставляйте `ROBOTS_MODE=dry` на Яндексе, а боевым работает GitHub. Сравните логи Яндекса с тем, что
приходит в Telegram: «ОТКРЫЛ БЫ» должно совпадать с настоящими открытиями GitHub-робота. Заодно видно, в
какое время срабатывает таймер.

## Шаг 9. Переключение (и откат)

Когда сухие прогоны чистые:
1. В Яндексе уберите переменную `ROBOTS_MODE` (или поставьте `live`).
2. **Сразу** отключите боевой GitHub-запуск, иначе сообщения придут дважды: GitHub → Actions →
   «Фоновые роботы…» → «…» → *Disable workflow*; в cron-job.org выключите задачу на `/tick`; Cloudflare-будильник
   (`GITHUB_PAT` в воркере) можно оставить — без включённого workflow он ничего не запускает.
3. Следите за уведомлениями 1–2 дня.

**Откат:** поставьте `ROBOTS_MODE=dry` (или отключите триггер) в Яндексе и включите workflow обратно на GitHub.
Ничего другого менять не нужно: база, ключи и скрипты остаются прежними.

## Что дальше по переезду

1. Воркер Telegram (меню, кнопки) остаётся на Cloudflare: Telegram оттуда доступен.
2. Сайт: Vercel → Object Storage + CDN Яндекса (статический сайт собирается `npm run build`).
3. База: Firebase → российское хранилище (YDB) — самый большой шаг, его делаем последним и отдельно.

## Проверка кода

`npm run test:yandexrobots` — шаги совпадают с workflow, диагностика не печатает секреты, обработчик
запускает шаги и не запускает шаг без `--dry` в сухом режиме. `npm run test:tgproxy` — прокси Telegram в воркере.
