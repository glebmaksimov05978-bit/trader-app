# Личный воркер TraderPro

Один воркер Cloudflare на два дела:

1. **`/` — кнопки под уведомлениями в Telegram.** Отвечает мгновенно и кладёт решение в
   очередь KV; раз в 15 минут GitHub Actions разбирает очередь и пишет решения в Firestore.
2. **`/order` — отправка заявки брокеру.** Кнопка «Купить сразу» в Калькуляторе.

Деплой: `npx wrangler deploy` из этой папки.

## Отправка заявок: что настроить

Пока не настроено — кнопки в приложении просто нет. Это сделано специально: кнопка,
которая всегда отвечает отказом, хуже отсутствующей.

### 1. Секреты (не попадают в репозиторий)

```
npx wrangler secret put TINKOFF_TRADE_TOKEN
npx wrangler secret put TINKOFF_ACCOUNT_ID
```

`TINKOFF_TRADE_TOKEN` — **новый** токен Т-Банка с правом торговли. Тот токен, что уже
используется в приложении для свечей и портфеля, — только на чтение, и таким он должен
остаться: он лежит в профиле и попадает в браузер. Торговый токен живёт ТОЛЬКО здесь и
в браузер не попадает никогда.

`TINKOFF_ACCOUNT_ID` — номер счёта, на который уходят заявки. Взять из
`UsersService/GetAccounts` или из приложения брокера.

### 2. Открытые настройки — в `wrangler.toml`, раздел `[vars]`

| Переменная | Что это |
|---|---|
| `FIREBASE_PROJECT_ID` | id проекта Firebase — по нему проверяется подпись входящего токена |
| `OWNER_UID` | ваш uid; заявка от любого другого пользователя будет отклонена |
| `ALLOWED_ORIGIN` | адрес приложения (CORS). Оставлять `*` не стоит |
| `TICKER_WHITELIST` | **единственный** список, по которому разрешено торговать: `SBER, GAZP, LKOH` |
| `MAX_ORDER_RUB` | необязательный потолок суммы одной заявки |

`TICKER_WHITELIST` пустой = **запрещено всё**. Молчание в настройках не открывает доступ
к деньгам.

### 3. Стоп-кран

```
npx wrangler secret put TRADING_DISABLED     # ввести: true
```

Мгновенно выключает отправку заявок целиком, не трогая ни уведомления, ни приложение.
Убрать — `npx wrangler secret delete TRADING_DISABLED`.

### 4. Адрес воркера в приложении

Поле `orderWorkerUrl` в профиле пользователя (или переменная сборки
`REACT_APP_ORDER_WORKER_URL`) — адрес этого воркера без завершающего слэша.

## Как это устроено и почему

- **Токен брокера не покидает сервер.** Браузер присылает намерение («купить SBER, 3
  лота, лимит 285») и Firebase ID-токен, доказывающий, что это владелец. Код в браузере
  открыт: любой секрет в нём — уже не секрет.
- **Тикер резолвится на сервере.** Если бы браузер присылал готовый `figi`, подменённый
  запрос купил бы что угодно. При резолве по тикеру белый список проверяет ровно то, что
  трейдер видит на экране.
- **Проверки на сервере, а не в интерфейсе.** Проверку в браузере может обойти кто угодно,
  включая ошибку в самом коде приложения.
- **Никакой автономии.** Заявка уходит только по нажатию человека: у воркера нет ни
  расписания, ни реакции на сигналы, ни способа отправить заявку самому.
- **Идемпотентность.** Браузер генерирует `requestId` один раз на окно подтверждения.
  Двойное нажатие или повтор после обрыва связи не превратятся в две заявки.
- **Сухой прогон.** Окно подтверждения сначала спрашивает сервер «что бы ушло», показывает
  его ответ и только потом даёт кнопку отправки. Этой же веткой ограничения проверяются
  тестами без единой настоящей сделки: `npm run test:orders`.
